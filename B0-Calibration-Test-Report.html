2. 三层测试设计

用户要求「做好测试开发」，所以不是只写方案：把 B0 拆成三层，每层都有独立断言， 并且三层都在 RealCue_API35 上真实跑过。main/ 源码一行未改。

层用例验证什么为什么不省
① 纯数学 statisticsLogicIsCorrect CalibrationMath 的百分位、可分 / 重叠 / 缺异人样本三种分支、 T_match / T_new、召回与误接受率 统计逻辑不依赖 Android / native，可被穷尽覆盖；错一位小数会直接把阈值带偏

③ 完整 pipeline calibrationPipelineWritesResultFile 读样本 → 提特征 → 同人 / 异人 pair 分数矩阵 → 写 JSON + CSV → 回读解析并断言字段一致 验证产物真的能用，而不是只在 logcat 里好看

4. 为什么这一轮结果「不可用于阈值」

链路验证时 A/ 与 B/ 放的是同一张 kun.jpg 的副本，所以同人 pair 与 异人 pair 的分数全部等于 1.0000，两段分布完全重合 —— 不存在 「同人最低分高于异人最高分」的间隔，任何阈值都无法同时做到高召回与零误接受。

这是设计中的正确行为 脚本打印的 T_match=1.0000 / T_new=0.8800 是数学输出， 但被 doNotUseForThreshold=true 明确否决，并以 NOT USABLE FOR THRESHOLD 收尾。不会有人拿它去填阶段 B 的三区阈值。

6. 防误用保护（核心代码）

boolean external = filesA.size() >= MIN_FEATURES_PER_PERSON
        && filesB.size() >= MIN_FEATURES_PER_PERSON;

boolean looksLikeSamePerson = external && !r.separable
        && r.diffMax >= (r.sameMin - 0.02f);
boolean unusable = !external || looksLikeSamePerson;

// JSON: "doNotUseForThreshold": unusable
// logcat: GUARD looksLikeSamePerson=true unusable=true

没有外部真人样本（纯自检 / 合成演练），或两段分布看起来像同一个人时， 一律不可用于阈值。这是「把测试做扎实」里最要紧的一条：宁可明确说「还没测出来」， 也不给出一个看起来漂亮但会误认人的数字。
