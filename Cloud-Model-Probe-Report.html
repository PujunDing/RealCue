5.thinking 模型的假阴性机制

qwen3-vl-4b-thinking 会先输出 reasoning_content（思维链）， 再输出 message.content。max_tokens 同时约束两者，所以预算太小就会出现 「HTTP 200、但什么也没答」：

指标max_tokens=128max_tokens=512
finish_reasonlength（被截断）stop（正常结束）
message.content空字符串非空中文问候
reasoning_content有，且占满预算有，但未耗尽预算
completion_tokens128（等于上限）268（小于上限）
若据此判定误判「模型不工作」正确判定「推理正常」

结论：不要用「HTTP 200 + 空 content」判定模型离线。 判据必须是 choices[0].message.content 非空；同时要检查 finish_reason=length 与 reasoning_content，把 thinking 截断和真故障区分开。

脚本的默认行为刻意保留了原始口径：先按 128 发一次（如实记录假阴性）， 识别到 finish_reason == "length" && content 为空 && reasoning_content 非空 后自动用 512 复测，两次结果都落盘，不掩盖第一次。

6.工具化：probe_model.py（v1.1）

  • 零依赖：仅 Python 标准库（urllib），不需要 curl / jq / requests。
  • 可移植：路径由脚本自身位置推导，无本机绝对路径；主机/端口/模型/提示词/token 全部可配置（CLI 或 REALCUE_MODEL_* 环境变量）。
  • 地址口径归一：默认服务地址 http://192.168.32.6:18090/v1； normalize_api_base() 同时接受带 /v1 与只给 origin 的写法， 端点统一为 /v1/models、/v1/chat/completions，不会重复拼 /v1。
  • 跨平台 ping：Windows 自动用 -n，Unix 用 -c；控制台输出按 ANSI 代码页解码，中文统计行不再乱码。
  • 默认绕过代理：等价于 curl --noproxy '*'；--use-proxy 可关闭。
  • 结构化落盘：汇总 JSON + 原始响应 JSON + meta.txt；汇总含 target.endpoints。
  • 明确退出码：0 通过 / 1 失败 / 2 结论不确定。

8.未来端云交互的接口约定

  1. 服务地址：http://192.168.32.6:18090/v1（API base）；端点 GET /models + POST /chat/completions，完整 URL 为 .../v1/models 与 .../v1/chat/completions。走配置或环境变量， 不硬编码；客户端也兼容只给 origin 再补 /v1 的写法。
  2. 模型发现：启动时取 data[0].id，不要把模型名写死在 APK 里。
  3. 非流式：stream: false；本探针只解析非流式响应，流式需另做解析。
  4. token 预算：max_tokens 可配置且默认给足（≥512）；必须处理 reasoning_content 与 finish_reason=length。
  5. 成功判据：以 choices[0].message.content 非空为准，HTTP 200 不等于推理成功。
  6. 网络：局域网直连、绕过系统代理；设超时；失败要能区分「连通性 / API / 推理」三段。
  7. 桥接前自检：先跑一次本探针，确认连通 / API / 推理三段都正常。

9.诚实边界与复现

  • 只证明「单次请求能拿到非空回复」，不测并发、长时稳定性、吞吐、模型精度或多轮上下文。
  • ping 失败不必然代表服务不可用（ICMP 可能被防火墙禁用），脚本不会因 ping 失败中断后续 HTTP 检查。
  • 目前只验证了 http://192.168.32.6:18090/v1 这一台局域网服务；换地址用 --base-url 或环境变量。
  • 本目录不包含、也不修改 app/src/ 下的 Android 业务源码；端侧接入尚未实现，这里是前置自检。
  • 云侧文档（README / 模型 README / NOTES / PLAN）不在本地工作区，本报告只覆盖 RealCue 仓库内可核实的文件。
