4为什么号码不会乱

机制解决的坑
长期 person_id 存在 FeatureHub 持久化库里，不随 camera Session 重建不再出现「退出再进来变 ID 2」
三区阈值：≥0.48 命中 / <0.36 判生人 / 中间继续采样一帧糊了不会立刻新建身份
连续 3 次无匹配才建档短暂遮挡、侧脸不会造成重复建档
同帧互斥（claimedThisFrame）同框两张脸不会都拿到 P001（串号）
轨迹 TTL + 离场清理（beginFrame / retainAll(seenTracks)）人走了绑定释放，但库记录保留；回来重新查库
自增主键 next_id，命中不消耗编号新人永远拿下一个空号，A 重入不会把号吃掉

视频页与图片页现在都走这套逻辑： FaceTrackingAnalyzer（视频）和 FaceDetectionActivity.resolveStableLabels()（图片） 都把每张脸的特征交给同一个 FaceRepository / FeatureHub。

5诚实边界（别夸大）

只有一张真人样本。项目里只有 kun.jpg （来自 InspireFace AAR 的 assets）。A 与 A 的重入是真实特征； B 和 C 是用 A 的特征构造的两个互不相似的合成向量 （-A 和「前半取反」），只用来验证「不同人 → 下一个号」的流程分支， 不是真人异人相似度，禁止用于阈值标定。
  • 阈值 T_match=0.48 / T_new=0.36 仍是 B0 占位值， 两个真人样本未采集。真人场景下陌生人误接受 / 误建档的风险还没测过。
  • 灰色区 FaceRepository.open() 用 SDK 推荐阈值设置 FeatureHub 搜索阈值，低分候选被提前过滤，生产线实际只有「高分命中 / 无候选」。
  • 环境 这次仍是 x86_64 模拟器 + 静态样本， 真机相机实时帧、多人同框、帧率、最终准确率都还没测。
  • APK 本轮测试本身只新增了 androidTest、没改 main/； 但随后已按「重新编译过没」的要求做了一次 --rerun-tasks 强制全量重编译， 交付包已更新为 116,455,212 B（2026-11-16 14:14:54），不再是旧的 117,605,130 B。 手机上的旧包不会自动更新，仍需重新上传安装才能看到 P001。

6真机上怎么验这条流程

  1. 确认手机上装的是最新重编译的 app-debug.apk （116,455,212 B / 2026-11-16 14:14:54；人物库按模型隔离，覆盖安装不会丢）。
  2. 打开你原来那个「人脸跟踪」页 → 切到「视频跟踪」。
  3. A 出镜，稳定约 1 秒后框上出现 P001。
  4. B 出镜（或让另一个人站进来），框上出现 P002；两人同框时两个号不同。
  5. A 完全离开画面几秒，再回来 → 应仍是 P001，不会变成 P003。
  6. 再来个新人 C → 应拿到 P003；去「人脸管理」能看到并能搜到这三个号。
如果真机上出现「A 回来变成新号」或「两个人同框都显示同一个号」， 把 logcat 里 RealCueTracking 的 STABLE_* 行发我， 我会按 SESSION_READY / STABLE_MATCHED / STABLE_ENROLLED / STABLE_ENROLL_FAILED 定位是阈值、特征提取还是轨迹绑定的问题。
