01一句话结论

可行，但分工必须重划。云端模型实测不接受音频输入（input_modalities = text / image / video，/v1/audio/transcriptions → 501）， 所以「声音同步抽取」必须在手机端完成：录音 → VAD → 语音转文字 → 说话人归属 → 与 P001 对齐， 只把结构化文字事件发给云端做理解与指导。

换句话说：端侧负责「看见谁、听见谁说了什么」，云端负责「接下来该怎么办」。

04推荐架构：端侧感知 + 端侧关联 + 云端决策

三条原则：① 端侧识别与关联、云端理解与决策，人脸特征 / 声纹 / 原始音频都不出端； ② VAD 检测到一句话结束才请求一次，同一句话去重；③ 时间戳统一到单调时钟，但先实测再信任（见 §05）。

端侧 ASR 候选

模型体积特点建议

工程约定：模型不进 APK，首次动态下载到应用私有目录并做 SHA-256 校验；否则 APK 从 116 MB 涨到 300 MB+，也突破 GitHub 单文件 100 MB 限制。

说话人归属：分两级

  • A 级（MVP）：画面只有一个人 → 语音直接归属该 P0xx，零额外模型、最可靠。
  • B 级（P2）：pyannote 切分 + CAM++（27 MB / 192 维）或 ERes2Net（111 MB）提声纹 + 聚类成 S0xx，建立 S ⇄ P 绑定。
  • C 级（P3）：唇动 / 朝向 / 空间位置辅助，处理同时说话；工程量最大，不建议起步就做。

多人场景允许输出 speaker: "UNKNOWN"，绝不强行绑定——错误绑定比不绑定更糟。

时间同步：最大工程风险（前置验证 V1）

CameraX 的 ImageInfo.getTimestamp() 是纳秒单调，但官方只保证同一相机实例内可比。它能否与 SystemClock.elapsedRealtimeNanos()（音频时钟）对齐，取决于 SENSOR_INFO_TIMESTAMP_SOURCE：

  • REALTIME：与 elapsedRealtimeNanos 同域，可比较，目标归属窗口 ±100 ms；
  • UNKNOWN：起点未知，不可与音频时钟比较 → 退化为「回调到达时间 + 实测偏移」并标注误差，或改用 Camera2；唇级同步（±20 ms）暂不承诺。

必须在目标真机（小米 14 Pro）上同时记录 camera timestamp / 音频 timestamp / 回调到达时间，跑 1 分钟统计偏差后再定方案。

06端 → 云事件协议（建议 schema）

{
  "schema": "realcue.interaction.v1",
  "session_id": "8f3a...",
  "clock": { "domain": "elapsedRealtimeNanos", "verified": true, "offset_ms": 0 },
  "window": { "start_ms": 10240, "end_ms": 13860 },
  "persons": [
    { "person_id": "P001", "present_ms": [10240, 13860], "conf": 0.97 }
  ],
  "utterances": [
    { "speaker": "P001", "start_ms": 10510, "end_ms": 11220,
      "text": "你好，你是谁？", "asr_conf": 0.86, "spk_conf": 0.71 }
  ],
  "request": "根据在场的人和对话内容，给出下一步交互建议。"
}

不出端的数据：原始 PCM、人脸 512 维特征、声纹 embedding、人脸图片（v1 不传；P3 若要让 VL 模型看图需单独授权传压缩 crop）。

云 → 端：用 system prompt 约束返回结构化 JSON，端侧只接受白名单动作 SPEAK / ASK / NOOP；其他一律拒绝，不允许云端直接控制相机或人物库。

07分阶段路线

P0前置验证

只验证假设，不做产品功能：① 真机时间戳源与偏差；② 云端结构化 JSON 连跑 20 次解析成功率；③ SenseVoice 加载时间 / 内存峰值 / 推理耗时。

验收：三项都有实测数字；V1 不过就降级为单人宽松时间窗。

P1MVP：单人 1:1

加 RECORD_AUDIO + 前台采集 + VAD + SenseVoice；只做 A 级归属；打通「一句话 → 云端 → 文本/TTS 指导」闭环。

验收：A 说话，云端回复带对 P001；静音不请求；端到端延迟有实测值。

P2多人说话人区分

加 CAM++ 声纹 + 聚类，建立 S0xx ⇄ P0xx；处理交替说话与同时说话（UNKNOWN）。

验收：A/B 交替归属正确率有统计，同时说话不串号。

P3增强

唇动 / 朝向辅助归属；授权后上传压缩人脸 crop 让 VL 模型看着人给指导；流式 ASR 降延迟。

验收：按具体指标另定。

需要你确认的 4 件事

  1. 「声音同步抽取」是否就是「录音 → 转文字 → 判断谁说的 → 与 P0xx 对齐」？
  2. 是否要求云端听原始声音或看人脸画面？（当前只能看画面，不能听；传图需额外授权）
  3. 云端指导要不要 TTS 播报，还是只显示在界面上？
  4. 长期遗留：新人拿 P003 还是复用空出来的 P002？
