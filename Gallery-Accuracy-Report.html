人物库 ID 与匹配准确性 · 实测报告

RealCue · InspireFace 1.2.4.post1 · Pikachu · 2026-11-15 · 设备 RealCue_API35 (Android 15 / API 35 / x86_64)

一句话结论：当前 APK 就能看到人物库分配的 ID（在 Face management / Face recognition / Face 1:1 页面），但实时画框上的数字是短时 track_id， 不是库 ID。实测同一个人 7 种画面变体 7/7 全部命中同一个库 ID 1001， 最低相似度 0.9680，而官方阈值只有 0.48 —— 模型层「离场再回来沿用旧号」是稳的。 但「准」还不能打包票：异人（不同人）分数分布在本机完全没测， 必须真机两个真人标定。

1. 你的两个问题，直接回答

Q1：能不能看到人物库给他分的是什么 ID？

能，不用改代码 去 Face management（列表里每条显示 ID · n）或 Face recognition（命中显示 ID · n · cosine confidence … · threshold …， 未命中也显示分数与阈值）就能看到。前提：库里得先有这个人 —— 官方 Demo 是 手动录入的，不会自动建档。 看不到 Face Tracking 页框上的 1 / 2 是 track_id，只在当前摄像头会话内稳定，离场必然变号，这正是你遇到的现象。

Q2：我希望这个比较准，现在准吗？

模型层：稳整体：还差一半证据 同人变体零漏匹配、分数高度集中（极差仅 0.032）、纯黑图不误建档 —— 说明 不是模型认不出人。但本机只有 kun.jpg 一张人脸， 异人分数分布完全空白；阈值 0.48 对这批变换偏宽松， 「把陌生人误认成已知人」的风险未知。所以不能说「已经准」， 只能说「沿用旧号这件事稳，剩下的不准来自应用层决策和未标定的异人阈值」。

4. 这些数字能说明什么、不能说明什么

能说明

  • 同一个人不会因为压缩、明暗、尺度、小角度旋转、镜像就被认成别人。
  • 只要库里有这个人，重新提特征查库就能拿回同一个 ID；配合已有的持久化测试，「离场再回来变号」不是模型认不出人。
  • 纯黑/无人脸帧不会凭空造特征、不会误建档，自动建档有安全底线。

不能说明

  • 这些是同一张静态图做数字变换，不是真机摄像头跨帧、跨姿态、跨表情、跨距离的真实变化。
  • 异人分数分布完全没测 —— 本机只有一张脸，造不出第二个真人。真正决定「准不准」的是「同人最低分」与「异人最高分」的间隔，现在只有上界、没有下界。
  • 阈值 0.48 对这批数据过于宽松：同人几乎不会漏，但陌生人分数落在 0.48~0.9 会怎样未知。风险是「误认成已知人」，不是「认不出熟人」。

5. 当前 APK 里，库 ID 到底在哪能看到

位置显示内容前提
首页 → Face management每条 ID · n + 名字已手动录入记录
Face recognition 命中ID · n · cosine confidence 0.xxx · threshold 0.480库非空且检索命中
Face recognition 未命中cosine confidence 0.xxx · threshold 0.480库非空
Face 1:1 比对cosine 分数 + 推荐阈值两侧各选一张脸

第三行是排障关键：未命中时也会显示实际分数和阈值。分数只比阈值低一点 → 阈值偏严或录入样本不够代表；差很多 → 角度、光照、遮挡或录入质量问题。 你现在就能在手机上用这个页面量一下自己的重入分数。

想让库 ID 自动出现在实时画框上（而不是 track_id），需要阶段 B 改造 + 重新构建 APK + 重新传到手机。现在手机上的 APK 是旧版，改源码不会自动生效。
